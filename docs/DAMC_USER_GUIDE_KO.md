# DAMC 사용 설명서

DAMC 1.2.0 · 처음 쓰는 사람을 위한 안내

---

## 1. DAMC란?

내 컴퓨터에서 돌아가는 **AI 장기 기억 저장소**다. ChatGPT나 Claude에서 내보낸 대화를
가져와 한곳에 모으고, 여러 AI가 MCP라는 표준 통로로 그 기억을 함께 읽고 쓴다.

DAMC는 생각하지 않는다. 기억만 한다. 생각은 AI가 한다.

자세한 배경은 [DAMC_PURPOSE.md](DAMC_PURPOSE.md).

## 2. 왜 사용하는가

- 대화창을 닫아도 맥락이 남는다
- ChatGPT에 설명한 내용을 다른 AI도 안다
- 기억이 내 디스크에 있다. AI 서비스를 바꿔도 남는다
- "왜 이렇게 하기로 했지"를 나중에 찾을 수 있다

## 3. 설치

**필요한 것: Docker Desktop.** DAMC는 컨테이너(앱 + PostgreSQL)로 돌기 때문에 반드시
있어야 한다. 없으면 설치 중에 안내가 나온다.

### Windows

1. `DAMC_Setup.exe` 실행
2. 안내를 따라 설치 (npm, node, git, 명령줄 작업은 필요 없다)
3. 설치가 끝나면 DAMC가 자동으로 시작된다

설치 프로그램이 순서대로 처리한다: Docker 확인 → 컨테이너 → PostgreSQL →
마이그레이션 → 백엔드 → 대시보드.

코드 서명이 되어 있지 않아 Windows가 "알 수 없는 발행자" 경고를 띄운다. 정상이다.

### macOS

현재 macOS 설치 패키지(.dmg)는 **제공되지 않는다.** 맥에서 쓰려면 Docker Desktop을
설치한 뒤 `docker compose`로 직접 띄워야 한다. 절차와 향후 계획은
[PRODUCTION_DEPLOYMENT.md](PRODUCTION_DEPLOYMENT.md)를 본다.

## 4. Dashboard 접속

브라우저에서 **http://127.0.0.1:8787**

처음 열면 이 브라우저가 스스로 API key를 받아온다. 이 기계에서 출발한 요청에만
허용되므로, 터널이나 외부에서는 불가능하다. 받은 key는 AI 연결 화면에 목록으로
보이고 언제든 취소할 수 있다.

시작/정지는 시작 메뉴에서 한다. 창은 뜨지 않는다 — 잠시 뒤 브라우저가 열리거나,
문제가 있을 때만 안내 창 하나가 뜬다.

```
시작 메뉴 → DAMC           시작(필요하면)하고 대시보드 열기
시작 메뉴 → Start DAMC     시작만
시작 메뉴 → Stop DAMC      정지 (데이터는 그대로)
시작 메뉴 → DAMC Status    진단용 상태 창
```

## 5. ChatGPT Export 가져오기

1. ChatGPT → 설정 → 데이터 제어 → 데이터 내보내기 → 메일로 받은 ZIP 저장
2. DAMC → **가져오기** → 파일 선택
3. **미리보기**를 먼저 누른다 (아무것도 저장하지 않고 몇 건인지 알려준다)
4. 확인 후 **가져오기** 실행

ZIP 그대로 넣어도 되고, 안의 `conversations.json`만 넣어도 된다. 여러 조각으로 나뉜
export도 지원한다.

실측 기준: 약 1.91GB / 3조각 ZIP → 미리보기 약 10초, 실제 가져오기 약 51초,
결과 236개 대화 / 5,296개 메시지 / 4,053개 기억.

## 6. Claude Export 가져오기

Claude는 파일을 바로 주지 않고 **`manifest-*.json`** 하나를 준다. 그 안에 패키지
목록과 1회용 다운로드 링크가 들어 있다.

1. Claude에서 내보내기를 요청해 `manifest-*.json`을 받는다
2. DAMC → 가져오기 → 그 manifest 파일을 넣는다
3. DAMC가 패키지 목록(보통 5개)을 보여준다
4. 각 패키지의 **[브라우저에서 다운로드]**를 누른다
5. 내려받은 파일이 `C:\DAMC_IMPORT`에 들어가면 DAMC가 알아서 가져온다

**브라우저 다운로드 폴더를 `C:\DAMC_IMPORT`로 지정하거나, 내려받은 파일을 그 폴더로
옮겨야 한다.** 안 그러면 감시 폴더를 비껴간다.

링크는 **한 번만** 쓸 수 있다. DAMC는 이미 쓴 링크를 기록해 다시 열지 않는다.
로그인과 봇 보호는 사용자의 브라우저가 처리하고, DAMC는 우회하지 않는다.

> **알려진 한계**: 실제 Claude archive 파싱은 아직 검증되지 않았다(NOT VERIFIED).
> manifest 인식·세션·감시 폴더·라우팅·가져오기 흐름은 검증되었지만, 진짜 Claude
> 아카이브가 도착한 적이 없어 그 내용 파싱은 확인하지 못했다.

## 7. Import 완료 확인

완료되면 **"가져오기가 완료되었습니다"**와 함께 실제 값이 나온다: provider, 파일,
대화 수, 메시지 수, imported, deduplicated, 기억/결정/작업 수, 완료 시각. 추측값은
표시하지 않는다.

진행 상태는 다음 중 하나다.

```
queued · awaiting_download · downloading · importing
completed · partial · failed · superseded
```

## 8. Memory란?

계속 참고할 사실. "이 프로젝트는 static HTML + Cesium 구조를 유지한다" 같은 것.

## 9. Decision이란?

확정된 선택. "앱을 일반판과 키즈판으로 나눈다" 같은 것.

결정이 바뀌면 DAMC는 옛 결정을 **지우지 않고** 대체(supersede)로 남긴다. 새 결정과
옛 결정이 둘 다 남고 왜 바뀌었는지가 보인다.

## 10. Task란?

앞으로 할 일. DAMC는 작업을 자동으로 완료 처리하지 않는다. 사람이나 AI가 명시적으로
상태를 바꿔야 한다.

## 11. Conversation / History란?

가져온 원본 대화와 메시지. 기억이 어느 대화의 어느 메시지에서 나왔는지 추적하는
근거가 된다.

## 12. 검색 방법

대시보드의 **기억** 화면에서 검색한다. 종류(Memory/Decision/Task)와 상태로 좁힐 수
있다.

한국어 검색은 트라이그램 색인을 쓴다. 형태소 분석기가 없어서 조사가 붙은 형태도
부분 일치로 찾는다. 의미 기반 벡터 검색은 없다.

## 12-1. Obsidian 연결

Obsidian은 AI가 아니라 **사람**을 위한 것이다. DAMC는 그래프를 직접 그리지 않는다.
기억마다 Markdown 노트 하나를, 관계는 위키링크로, `C:\DAMC_OBSIDIAN` 폴더에 쓰고,
Obsidian의 Graph View가 그것을 그린다.

1. 대시보드 → **Obsidian** → [Obsidian 동기화]
2. Obsidian에서 "폴더를 보관소로 열기" → `C:\DAMC_OBSIDIAN`
3. Graph View 열기

동기화는 한 방향이다. 수정은 DAMC에서 하고 다시 동기화한다. DAMC가 원본이고
Obsidian은 보기 화면이다.

```
DAMC     = 장기 기억
Hermes   = AI 에이전트
Obsidian = 사람이 보는 지식 화면
```

## 13. AI Connection Center

**AI 연결** 화면. 어떤 AI가 DAMC를 실제로 쓰고 있는지 보여준다.

각 AI마다 표시되는 것: 연결 상태, transport, endpoint, tool 개수, 인증 상태, 마지막
활동 시각, 그리고 읽기/쓰기 이력.

상태는 **서버에 남은 증거**로만 정해진다.

| 표시 | 뜻 |
|---|---|
| 설정 안 됨 | key도 활동도 없음 |
| 설정됨 | key는 있으나 이 AI가 나타난 적 없음 |
| 인증됨 | 접속은 했으나 tool 호출 없음 |
| 읽기 확인 / 쓰기 확인 | 과거에 읽거나 쓴 적 있음 |
| 활성 | 최근 1일 안에 호출 있음 |

"설정됨"과 "활성"은 다르다. 설정 파일에 적혀 있는 것만으로는 연결되었다고 하지
않는다.

DAMC는 컨테이너 안에 있어서 내 PC에 어떤 AI가 설치되어 있는지는 알 수 없다. 그래서
"설치됨/미설치"를 주장하지 않고, 호출 이력만 보여준다.

## 14. Hermes 연결

Hermes Agent를 쓰면 22개 tool 전체를 사용할 수 있다. 순서는 [AI 연결 화면의 Hermes
설정] 또는 [integrations/hermes/SETUP.md](../integrations/hermes/SETUP.md).

요약:

1. DAMC에서 API key 생성
2. Hermes `.env`에 `MCP_DAMC_API_KEY=<key>` (config 파일에 직접 적지 않는다)
3. Hermes `config.yaml`에 `mcp_servers.damc` 추가
4. `tools.tool_search.enabled: "off"` 추가 — **이걸 빼면 연결은 되지만 AI가 DAMC를
   쓰지 않는다**
5. 텔레그램 등을 쓰면 `hermes gateway restart`
6. `hermes mcp test damc` → connected, 22 tools

## 15. Hermes가 DAMC를 사용하는 방식

Hermes 자체 기억(`MEMORY.md` / `USER.md`)은 작고 문자 수 상한이 있다. 거기에는 항상
참인 핵심만 둔다 — 내가 누구인지, 어떻게 일하는지, 그리고 **장기 기억은 DAMC에
있다는 사실**.

과거를 묻는 질문("예전에 정한 게 뭐였지")이 오면 Hermes가 DAMC를 먼저 검색한다.
일반 상식 질문에는 검색하지 않는다 — 불필요한 조회는 비용이다.

DAMC의 내용을 Hermes 기억 파일에 복사하지 않는다. 상한 때문에 들어가지도 않는다.

## 16. 중복 Import

같은 export를 다시 넣어도 안전하다. DAMC가 내용 해시로 중복을 걸러낸다.

실측: 같은 1.91GB export 재실행 → 236건 감지, **imported 0 / deduplicated 236**,
새 기억 0건.

## 17. 대용량 Import

DAMC는 export를 스트리밍으로 읽는다. 업로드 → 임시 파일 → ZIP 항목 → 대화 하나씩.
전체를 메모리에 올리지 않기 때문에 export가 커도 메모리가 비례해 늘지 않는다.
2GB급에서 컨테이너 메모리 1GiB 미만으로 확인되었다.

## 18. 오류가 발생했을 때

| 증상 | 확인할 것 |
|---|---|
| 대시보드가 안 열림 | Docker Desktop 실행 중인지, `damc-status.cmd` |
| 파일이 너무 크다는 오류 | `DAMC_IMPORT_MAX_FILE_SIZE_BYTES` 상향 |
| 가져오기가 실패로 끝남 | 파일이 온전한지. 중간에 끊긴 다운로드가 흔한 원인 |
| Claude 링크가 안 열림 | 1회용 링크를 이미 썼거나 만료됨. 새 export 요청 |
| AI가 DAMC를 안 씀 | 그 AI의 tool 지연 설정. Hermes는 §14의 4번 |
| 키를 잃어버림 | 브라우저에서 대시보드를 다시 열면 새 key를 받는다 |

## 19. 데이터 보존

기억은 Docker 볼륨(`damc_damc_pg`)에 있다.

- **재설치**해도 지워지지 않는다
- **업그레이드**해도 보존된다
- **삭제(uninstall)**해도 볼륨은 남는다

완전히 지우려면 설치 폴더의 `damc-uninstall-cleanup.cmd`를 `purge` 인자로 직접
실행해야 한다. 실수로 지워지지 않게 일부러 이렇게 해 두었다.

기억은 수정해도 옛 버전이 남는다. 결정은 대체로 남는다.

## 20. 보안

- 앱은 `127.0.0.1`에만 열린다
- **PostgreSQL은 호스트에 포트를 열지 않는다.** 컨테이너 네트워크 안에서만 접근된다
- 모든 `/v1` 요청에 API key가 필요하다 (production 기준)
- key는 해시로 저장되고, 생성 직후 한 번만 보인다
- `/health`에 비밀값이 실리지 않는다
- 업로드한 파일에서 나온 URL은 호스트 허용목록으로 검증하고, 리다이렉트마다 다시
  검증한다
- 가져오기는 악성 압축 파일을 크기·항목 수 상한으로 막는다

한계도 분명히 적는다. PostgreSQL 비밀번호는 고정값이고(포트를 닫아 완화), 신뢰
경계는 이 기계 자체다. 내 계정으로 도는 프로세스는 저장된 key를 읽을 수 있다. DAMC는
1인용 로컬 저장소이며 계정이 침해된 상황을 방어하지 않는다.

**어떤 AI 설정 파일에도 key를 평문으로 적지 않는다.** 환경변수 참조를 쓴다.

## 21. Demo data 없음

설치 직후 모든 수치는 0이다.

```
기억 0 · 결정 0 · 작업 0 · 대화 0 · 메시지 0 · 프로젝트 0 · 가져오기 0
```

샘플 데이터를 넣지 않는다. 자동 seed도, 화면용 가짜 대체값도 없다. 빈 화면에는
안내문만 나오고 그 안내문이 DB에 행을 만들지는 않는다. 이 규칙은 테스트로 고정되어
있다.

## 22. DAMC와 AI의 역할 차이

```
DAMC   = 기억한다
AI     = 생각하고 실행한다
MCP    = 둘을 잇는다
```

DAMC는 AI를 대신하지 않고, AI는 기억을 소유하지 않는다. DAMC가 AI의 내부 데이터를
직접 고치지도 않는다.

## 23. 기본 사용 예시

**처음 설치한 날**

1. 설치 → 대시보드 열기 → 비어 있음 확인
2. ChatGPT export 가져오기
3. 기억 화면에서 검색해 보기
4. AI 연결 화면에서 key 만들고 Hermes 연결
5. Hermes에게 "예전에 정한 거 뭐였지" 물어보기

**평소**

- 중요한 결정이 나오면 AI에게 "이거 기억해"라고 한마디
- 새 대화를 시작할 때 AI가 DAMC에서 맥락을 꺼내오게 한다
- 몇 달에 한 번 export를 다시 가져온다 (중복은 자동으로 걸러진다)

## 24. 자주 묻는 질문

**인터넷이 필요한가?**
DAMC 자체는 아니다. 다만 Docker 이미지를 처음 받을 때와, 원격 접속 기능을 쓸 때는
필요하다.

**내 대화가 외부로 나가는가?**
DAMC는 내보내지 않는다. 다만 AI 클라이언트가 DAMC에서 읽은 내용을 자기 모델에
보내는 것은 그 AI의 동작이다.

**여러 AI가 같은 기억을 보는가?**
그렇다. 그것이 목적이다. 단, 각 AI를 각자 연결해 주어야 한다.

**AI가 내 기억을 마음대로 지울 수 있는가?**
삭제 도구는 없다. 수정은 버전으로, 결정 변경은 대체로 남는다.

**가져온 기억이 이상하게 장황하다**
대화 로그에서 자동 추출한 것이라 그렇다. `candidate` 상태인 항목은 확정 사실이 아니다.
앞으로 AI가 `session_save`로 쌓는 기억이 훨씬 정제되어 있다.

**tool 결과의 `count`가 실제보다 작다**
`count`는 그 페이지의 길이이고 전체 개수가 아니다. 이 tool들에는 페이지 커서가 없다.

**Mac에서 쓸 수 있는가?**
Docker + compose로 가능하다. 전용 설치 패키지(.dmg)는 아직 없다.

**업데이트는 어떻게?**
새 설치 파일을 실행하면 덮어쓴다. 데이터는 보존된다.
