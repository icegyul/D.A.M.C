# DAMC는 무엇이고, 왜 필요한가

DAMC = **D**alur **A**I **M**emory **C**enter.

한 문장으로: **여러 AI가 함께 쓰는, 내 컴퓨터에 있는 장기 기억 저장소.**

---

## 무엇을 해결하는가

AI를 오래 쓰면 같은 문제가 반복된다.

**대화가 끝나면 사라진다.** 어제 세 시간 걸려 정한 설계를 오늘 그 AI는 모른다.
대화창을 닫으면 맥락이 사라지고, 다음 대화는 다시 처음부터 설명해야 한다.

**AI마다 기억이 따로 있다.** ChatGPT에게 설명한 프로젝트 구조를 Claude는 모른다.
Cursor는 또 모른다. 같은 이야기를 세 번 한다.

**기억이 그 회사 서버에 있다.** 내가 쌓은 맥락인데 내가 꺼낼 수도, 옮길 수도 없다.
서비스를 바꾸면 기억도 버려야 한다.

**중요한 결정과 잡담이 섞여 있다.** "이건 이렇게 가기로 했다"와 "오늘 날씨"가 같은
로그 안에 뒤섞여 있어서, 정작 필요할 때 찾을 수 없다.

DAMC는 이 네 가지를 겨냥한다. 기억을 **내 컴퓨터의 PostgreSQL 한 곳**에 모으고,
여러 AI가 **MCP**라는 표준 통로로 그 하나를 함께 읽고 쓰게 한다.

---

## 네 단어로 본 구조

```
DAMC      = 기억   (Memory)
Agent     = 실행   (Execution)
MCP       = 연결   (Connection)
Projects  = 일     (Work)
```

- **DAMC**는 생각하지 않는다. 기억한다.
- **Agent**(Hermes, Claude, Cursor 등)는 기억하지 않는다. 생각하고 실행한다.
- **MCP**는 그 둘을 잇는 표준 규약이다. 특정 회사 것이 아니다.
- **Projects**는 기억을 일 단위로 묶는 축이다.

```
                      ┌──────────────────────┐
                      │        DAMC          │
                      │  장기 기억 (내 PC)    │
                      │                      │
                      │  Memory              │
                      │  Decision            │
                      │  Task                │
                      │  Conversation        │
                      └──────────┬───────────┘
                                 │  MCP Server
                 ┌───────────────┼───────────────┐
                 ▼               ▼               ▼
              Agent A         Agent B         Agent C
            (MCP client)    (MCP client)    (MCP client)
```

중요한 것은 방향이다. **DAMC가 AI를 부르지 않는다. AI가 DAMC에 접속한다.**
그래서 AI를 바꾸거나 늘려도 기억은 그대로 남는다.

---

## DAMC가 저장하는 네 가지

| 종류 | 뜻 | 예 |
|---|---|---|
| **Memory** | 계속 참고할 사실 | "이 프로젝트는 Cesium 기반 3D 지구를 쓴다" |
| **Decision** | 확정된 선택 | "앱을 일반판과 키즈판 두 개로 운영한다" |
| **Task** | 앞으로 할 일 | "실제 export archive 파싱 검증" |
| **Conversation** | 원본 대화 | 가져온 ChatGPT/Claude 대화 전문 |

Decision과 Memory를 나누는 이유는 실무에서 다르게 쓰이기 때문이다. "무엇이
사실인가"와 "무엇을 하기로 했는가"는 다른 질문이고, 나중에 뒤집히는 쪽은 보통
후자다. 그래서 DAMC는 결정을 덮어쓰지 않고 **supersede**(대체)로 남긴다 — 새 결정과
옛 결정이 둘 다 남고, 왜 바뀌었는지가 보인다.

## 설계 원칙

**내 컴퓨터에 있다.** 기본 구성은 `127.0.0.1`에만 열린다. 클라우드 계정도, 외부 전송도
없다. PostgreSQL은 호스트에 포트조차 열지 않는다.

**AI 회사에 묶이지 않는다.** 저장 형식은 DAMC의 것이고, 통로는 MCP 표준이다. 어떤
AI가 없어져도 기억은 남는다.

**추측을 사실로 만들지 않는다.** 대화에서 뽑아낸 항목은 `candidate`로 들어간다.
근거가 약한 추출은 확정 사실을 밀어내지 못하고, 모순되는 내용은 양쪽 다 남긴 채
`CONFLICT_PENDING`으로 표시된다.

**옛 기억을 지우지 않는다.** 수정은 버전으로 쌓이고, 대체는 관계로 남는다.

**데모 데이터를 넣지 않는다.** 설치 직후 화면은 정직하게 비어 있다. 샘플 기억이
내 기억처럼 보이는 상황을 만들지 않는다.

**가져온 것의 출처를 지운다 해도 원본은 남긴다.** 어떤 대화의 어떤 메시지에서 나온
기억인지 추적할 수 있다.

---

## 이런 사람에게 맞다

- 한 프로젝트를 몇 달 이상 끌고 가면서 AI와 계속 일하는 사람
- ChatGPT/Claude를 오래 써서 내보낼 대화가 수백 건 쌓인 사람
- 여러 AI 도구를 함께 쓰는데 매번 같은 설명을 반복하는 사람
- 내 맥락이 남의 서버에만 있는 상태가 불편한 사람

## 이런 용도는 아니다

- 팀 공유 지식베이스 — DAMC는 1인용 단일 사용자 저장소다
- 의미 기반 벡터 검색 — 현재 검색은 전문 검색 + 트라이그램이다
- AI 실행 환경 — DAMC는 생각하지 않는다
